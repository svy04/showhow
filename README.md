# showhow

**하던 일만 하세요. 문서는 알아서 남습니다.** 업무 화면을 자동으로 담아 PDF·PPT·워드로 내보내는, 브라우저 파일 하나짜리 도구입니다.

[English](README.en.md) · [바로 써보기](https://svy04.github.io/showhow/) · [파일로 내려받기](https://github.com/svy04/showhow/raw/main/index.html)

- **클릭 없이도 담깁니다.** 타이핑, 단축키, 창이 뜨는 것, 로딩이 끝나는 것까지 화면이 바뀌면 담깁니다.
- **멈출 때 한 장씩만 담깁니다.** 커서가 지나가거나 영상이 도는 동안에는 담지 않습니다.
- **놓친 순간을 되살립니다.** 안 담긴 화면도 최근 것은 되감아 꺼낼 수 있습니다.
- **PDF·PPT·워드·파일 한 장으로 내보냅니다.** 파워포인트와 워드 파일은 받은 사람이 그대로 고쳐 쓸 수 있습니다.
- **받는 사람에 따라 잘라 냅니다.** 섹션을 빼면 그 섹션은 내보내기에서 통째로 빠집니다.
- **사진이 컴퓨터를 벗어나지 않습니다.** 서버로 보내는 코드가 없습니다. 인터넷이 끊겨도 됩니다 (제목 자동 작성만 예외 — 아래 참조).
- **제목 초안을 대신 씁니다.** 바뀐 자리의 글자를 읽어 「다음 누르기」처럼 채웁니다. 흔한 단추 16개를 크기 네 가지로 그려 64번 시켜 **44번 맞혔습니다**(틀림 10 · 빈칸 10). 읽는 일도 이 컴퓨터 안에서 합니다.
- **검사 498건이 통과한 상태로 배포합니다.** 그중 349건은 진짜 브라우저에서, 8건은 실제로 새로고침해서, 10건은 대역 없는 진짜 화면 공유로 돌립니다.

4. 그다음부터는 하던 일만 합니다.

## 무엇이 다른가

화면 캡처형 매뉴얼 도구는 대부분 **클릭이 있어야 사진이 생깁니다.**

> "StepCapture records cursor clicks and drags, but does not capture non-click actions, such as text entry or keyboard shortcuts."
> — [Snagit 공식 문서](https://www.techsmith.com/learn/tutorials/snagit/create-step-by-step-instructions/) (2026-08-21 확인)

> "Recorded steps don't capture anything that's typed during the recording."
> — [Microsoft 단계 기록기 공식 문서](https://support.microsoft.com/en-us/windows/record-steps-to-reproduce-a-problem-46582c9b-620f-2e36-00c9-04e25d784e47) (2026-08-21 확인)

그래서 다 만들고 나서 보면 빠진 단계가 생깁니다. 편집이 늦어서가 아니라, 그 순간 클릭이 없어 사진이 아예 안 만들어졌기 때문입니다.

showhow 는 클릭 대신 **화면이 얼마나 바뀌었는지** 를 봅니다. 초당 7번 화면을 비교해서, 크게 바뀌기 시작한 뒤 **0.7초 동안 그대로면** 한 장을 담습니다.

0.7초를 세는 이유가 있습니다. 화면 공유는 초당 다섯 장을 보내는데 우리는 초당 일곱 번 보기 때문에, 같은 장면을 두세 번 다시 보는 일이 늘 생깁니다. 그것을 "멈췄다"로 읽으면 영상이 도는 내내 사진이 쌓입니다. 그래서 횟수가 아니라 시계로 잽니다.

| 무엇을 할 때 | 클릭으로 찍는 도구 | showhow |
|---|---|---|
| 버튼을 누른다 | 담김 | 담김 |
| 칸에 글자를 친다 | 안 담김 | 담김 |
| 단축키를 누른다 | 안 담김 | 담김 |
| 창이 뜨거나 로딩이 끝난다 | 안 담김 | 담김 |
| 커서만 지나간다 | 담김 (지워야 함) | 안 담김 |
| 영상이 돌아간다 | 계속 담김 | 안 담김 |

한 번에 오래 움직인 화면은 3초 동안 "영상"으로 기억해 두고, 그동안은 1.5초를 기다립니다. 그래서 스크롤이나 영상에서 사진이 쌓이지 않습니다.

화면이 너무 오래 쉬지 않아 담지 못하고 있으면 그렇게 말해 줍니다. 그때는 <kbd>Space</kbd> 로 직접 찍으면 됩니다.

찍는 동안에는 이 창을 안 보게 됩니다. 그래서 **탭 제목이 대신 알려 줍니다** — `3장 · 담는 중 — showhow`.

## 담긴 것을 다듬는다

담기는 동안 오른쪽 목록에 쌓입니다. 제목만 달면 문서가 됩니다.

![단계 목록](docs/2_단계.png)

바뀐 자리는 빨간 테두리로 표시되고, 설명 칸에는 `오른쪽 아래 부분이 바뀌었습니다` 같은 길잡이가 흐리게 뜹니다. 길잡이는 예시일 뿐이라 내보낼 때 문서에 들어가지 않습니다.

### 제목은 초안까지 나옵니다

**제목 자동 작성**을 켜면 바뀐 자리의 글자를 읽어 「다음 누르기」처럼 제목을 채웁니다. 채운 제목에는 **짐작** 표시가 붙습니다 — 읽은 것이지 안 것이 아니기 때문입니다.

얼마나 맞히는지 재 두었습니다. 흔한 단추 16개를 크기 네 가지로 그려 64번 시켰습니다.

| | 맞음 | 틀림 | 빈칸 |
|---|---|---|---|
| 전체 64개 | 44 | 10 | 10 |
| 한글 40개 | 26 | — | — |
| 영어 24개 | 18 | — | — |

`node tests/검사_제목.mjs` 로 직접 다시 잴 수 있습니다. 검사는 **맞음 40 · 한글 24 · 영어 16** 아래로 떨어지면 실패합니다 — 실측(44 · 26 · 18)에서 네 개까지만 봐줍니다.

한 단계에서 할 수 있는 것:

- **표시하기** — 상자·화살표·번호·글자를 넣고, 가려야 할 곳은 덮고, 사진을 잘라 냅니다. 색 다섯 가지, 굵기 세 단계, 표시 하나만 지우는 지우개.
- **위와 합치기 / 둘로 나누기 / 복제** — 한 동작이 두 장으로 찍혔거나 그 반대일 때.
- **끌어서 옮기기** — 번호 동그라미를 잡고 끕니다. 두 번 누르면 맨 위로. Ctrl+Z 로 되돌리고 Ctrl+Shift+Z 로 다시 실행합니다.
- **섹션 넣기** — 단계를 묶고, 받는 사람에 따라 통째로 뺍니다.
- **여러 개 한꺼번에** — 번호를 누르면 골라지고, Shift 로 누르면 사이가 통째로 골라집니다. 골라 놓고 한 번에 지우거나 섹션으로 묶습니다.
- **찾기와 바꾸기** — <kbd>Ctrl</kbd>+<kbd>F</kbd> 로 제목·설명에서 찾습니다. 찾은 말은 한 번에 바꿉니다. 용어 하나가 바뀌었을 때 예순 단계를 손으로 안 고쳐도 됩니다.
- **사진 넣기·갈아 끼우기** — 자동으로 못 담은 화면은 그림 파일을 창에 끌어다 놓으면 그 자리에 들어갑니다. 잘못 담긴 사진은 갈아 끼웁니다.

## 내보낸다

![내보내기](docs/3_내보내기.png)

| 무엇으로 | 언제 씁니까 |
|---|---|
| PDF | 종이로 뽑거나, 어디서나 똑같이 보이게 보낼 때 |
| PPT | 발표하거나, 받는 사람이 고쳐 쓰게 할 때 |
| 워드 | 사내 문서 양식에 맞춰 이어 쓸 때 (한글에서도 열립니다) |
| 파일 한 장 | 두 번 눌러 바로 열게, 프로그램 없이 보낼 때 |
| 사진 원본 | 다른 문서에 사진만 붙여 넣을 때 |
| 글과 그림 | 위키·깃헙·노션에 옮겨 붙일 때 |
| 먼저 보기 | 보내기 전에 받는 사람 눈으로 한 번 볼 때 (새 탭에 그대로 엽니다) |

내보낸 파일에는 날짜가 붙습니다 — `청구 넣기_2026-08-21.pptx`. 내려받기 폴더에 `(1)` `(2)` 가 붙기 시작하면 어느 것이 최신인지 아무도 모르게 됩니다.

파워포인트와 워드 파일은 외부 라이브러리 없이 직접 만듭니다. 만든 XML 이 문법에 맞는지 검사에서 실제로 파싱해 확인합니다.

PDF 는 브라우저 인쇄를 씁니다. 한글이 그림이 아니라 글자로 들어가서 복사·검색이 됩니다.

## 회사 양식을 저장한다

표지, 머리말, 맺음말을 양식으로 저장해 두고 매번 불러 씁니다. 부서마다 다른 양식을 `.manualform.json` 파일로 주고받을 수 있습니다.

매뉴얼이 여러 개면 목록에서 골라 이어 씁니다. 비슷한 것은 복제해서 고쳐 씁니다.

![매뉴얼 목록](docs/4_목록.png)

## 어디에 저장됩니까

| 무엇이 | 어디에 | 언제까지 |
|---|---|---|
| 사진까지 든 정본 | 브라우저의 큰 저장칸(IndexedDB) | 브라우저 기록을 지우면 사라집니다 |
| 사진을 뺀 글 | 브라우저의 작은 저장칸 | 같음 — 큰 칸이 잘못돼도 글은 남습니다 |
| 예전 판 다섯 벌 | 큰 저장칸 | 열 분마다 한 벌씩, 여섯 벌째부터 오래된 것을 지웁니다 |
| 작업 파일 | 내가 고른 폴더 | 내가 지울 때까지 |

사진은 작은 저장칸에 넣지 않습니다. 그래서 사진이 아무리 많아도 저장칸이 차서 막히는 일이 없습니다.

다만 브라우저가 큰 저장칸(IndexedDB)을 막아 둔 환경(사생활 보호 모드 등)에서는 작은 칸으로 물러섭니다. 그때는 사진도 작은 칸에 들어가고, 차면 화면 위에 **저장이 안 되고 있다**고 알립니다. 그 알림이 뜨면 **작업 저장**으로 파일을 뽑아 두십시오.

고치다 크게 어긋났으면 **매뉴얼 목록** 아래의 예전 판으로 돌아갈 수 있습니다. 되돌리기(Ctrl+Z)가 닿지 않는 자리까지 갑니다.

만든 것은 전부 이 브라우저 안에만 있습니다. 컴퓨터를 바꾸거나 브라우저를 청소하면 같이 사라집니다. **매뉴얼 목록 → 전부 파일 하나로** 로 통째로 싸서 옮기십시오. 받는 쪽에서는 **파일에서 전부 가져오기** 로 풉니다. 이름표가 겹쳐도 있던 것을 덮지 않고 나란히 둡니다.

## 밝혀 둘 것 여섯 가지

1. **제목 자동 작성만 주소로 열었을 때 됩니다.** 글자를 읽는 파일이 `ocr/` 폴더에 따로 있어서, 내려받은 `index.html` 하나만으로는 브라우저가 옆 폴더 읽기를 막습니다. [바로 써보기](https://svy04.github.io/showhow/) 로 열거나 저장소를 통째로 받아 회사 안 서버에 두면 됩니다. 이때도 사진은 나가지 않습니다 — 글자 읽기까지 이 컴퓨터 안에서 합니다.
2. **크롬·엣지에서 검사했습니다.** 파이어폭스·사파리에서는 돌려보지 않았습니다. 확인하려면 그 브라우저로 열고 `tests/검사_촬영.mjs` 가 하는 절차를 손으로 밟으면 됩니다.
3. **화면 고르기 창은 사람이 한 번 눌러야 열립니다.** 브라우저 규칙이라 프로그램이 대신 누를 수 없습니다. `tests/검사_진짜공유.mjs` 는 그 창까지 브라우저 실행 옵션으로 자동으로 고르게 해서, 대역 없이 진짜 화면 신호로 돌립니다.
4. **고른 화면에 이 창이 보이면 자기 자신이 찍힙니다.** 한 장 담길 때마다 목록이 길어져 화면이 또 바뀌기 때문입니다. 실측으로는 사진 3장쯤에서 저절로 멎고, 더 빠르게 이어지면 자동 촬영을 끄고 이유를 알려 줍니다.
5. **링크로 공유하는 기능은 없습니다.** 서버가 없기 때문입니다. 대신 **파일 한 장으로** 를 쓰면 받는 사람이 두 번 눌러 바로 엽니다.
6. **소리와 영상은 담지 않습니다.** 화면 사진과 글만 남습니다.

`tests/검사_브라우저_길.js` 는 안쪽 함수를 부르지 않습니다. 화면의 단추를 누르고, 파일 고르기 창에 파일을 얹고, 키를 눌러서만 확인합니다 — 그 사이에 있는 배선이 끊겨도 잡히게.

`tests/검사_브라우저_약속.js` 는 화면이 한 약속을 물건이 지키는지 봅니다 — 「가릴 곳은 원본에서도 지워집니다」는 사진 픽셀로, 「사진은 둘 다 남습니다」는 나온 PPT·워드·마크다운·사진묶음 안을 열어서.

`tests/검사_저장.mjs` 는 페이지를 진짜로 새로고침합니다. 쉬지 않고 글을 치는 동안에도 정본이 써지는지, 다 지운 뒤 새로고침해도 되살아나지 않는지, 저장이 실패했을 때 "저장됨"이라고 하지 않는지를 잽니다.

`tests/검사_기능표.mjs` 는 상용 제품이 가진 기능 34가지를 이 코드가 실제로 갖고 있는지 파일에서 확인합니다. 사람 기억이 아니라 파일이 근거입니다. 그중 상용이 돈 받는 것으로 확인된 14가지를 무료로 제공하고, 값을 확인하지 못한 13가지는 확인 못 했다고 적어 둡니다.

`tests/검사_브라우저_규격.js` 는 화면 값이 규격에서 벗어나지 않았는지 잽니다 — 본문 17px, 행간 1.5, 폭 680px 은 그 값으로 못 박고, 글자 대비는 **4.5:1 이상**을 요구합니다(실측 본문 11.3:1 · 제목 16.6:1). 색·간격·모서리는 **디자인 시스템 토큰만** 쓰게 하고 날값을 쓰면 걸러 냅니다.

`tests/검사_진짜공유.mjs` 는 대역을 하나도 쓰지 않습니다. 진짜 `getDisplayMedia` 가 돌려주는 진짜 화면 신호로 담고, 자기 자신을 찍는 고리까지 실제로 만들어 봅니다.

## 이 도구로 만든 문서

말로 설명하는 대신 실물을 놓습니다. **[showhow 쓰는 법](https://svy04.github.io/showhow/docs/showhow-%EC%93%B0%EB%8A%94%EB%B2%95.html)** — 이 문서는 손으로 쓴 것이 아니라 showhow 가 담은 것입니다.

창 두 개를 띄워, 한쪽이 다른 쪽의 화면을 진짜로 공유해서 담았습니다. 대역은 없습니다. 제목과 설명만 사람이 달았습니다.

![직접 만든 문서](docs/8_만든문서.png)

직접 다시 만들어 볼 수 있습니다.

```bash
node tests/만들기_사용법.mjs     # 창 두 개가 잠깐 뜹니다
```

## 이 도구가 나온 이유

2026년 8월 17일, 한 사용자가 이런 것을 찾는다고 썼습니다. 화면을 캡처하고, 제목과 내용을 쓰고, 기호로 표시하고, 프로젝트와 섹션으로 정리하고, PDF·PPT 로 내보내고, 이미지 원본은 따로 저장하고, 회사·부서별 양식을 저장하는 것. 무료이거나 오픈소스면 좋겠다고 했습니다.

덧붙인 말이 이 도구의 방향을 정했습니다. **"나중에 편집하려면 빠진 게 있을 때도 있어서."**

그가 쓴 일곱 가지가 실제로 다 들어갔는지는 말이 아니라 검사로 확인합니다.

```bash
node tests/검사_요청대조.mjs
```

```
── 요청한 사람이 쓴 일곱 가지 ──
됨    ① 스크린샷 캡처      ② 제목·내용 작성      ③ 기호 등 편집 기능
됨    ④ 프로젝트·섹션 정리   ⑤ PDF·PPT 내보내기   ⑥ 이미지 원본 별도 저장
됨    ⑦ 양식 저장·불러오기 · 회사·부서별로 지정

── 요청한 사람이 '어려울 것 같다'며 뺀 것 ──
됨    영상처럼 보고 편집점 잡기 · 놓친 편집점 되살리기
```

그가 어렵겠다며 스스로 뺀 것까지 넣었습니다.
